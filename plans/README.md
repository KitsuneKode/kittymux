## Findings verified during the audit and NOT planned

- **`kitty @ kitten` calls without `timeout=`** (`bin/kittymux` ~2193, ~2226 for peek/join) — *correct as-is*:
  these block while the user interacts with the TUI overlay; a timeout would kill a picker mid-use. Do not "fix".
- **`_maybe_autosave`'s `hash(tuple(sorted(window_ids)))`** — fine: the signature only compares within one kitty
  process, where `hash()` is stable; a theoretical collision only delays a save until the 15-min period fires.
- **Unlocked read-modify-write in `kittymux_quiet` (snooze/mute) and `kittymux_fanout.save`** — real but a CLI-only
  race between a human's two terminals; journal's flock pattern is available if it ever bites. Revisit only if a
  second writer appears.
- **`hyprctl` subprocess inside geninclude on every reload** (`kittymux_layout.py` ~139–149): up to ~1 s worst case
  on a hung Hyprland per config reload. Acceptable today (it's why `window_alert_on_bell no` is emitted correctly);
  cache the verdict in state dir only if reloads ever feel slow.
- **`on_tab_bar_dirty` watcher → push model for `mux-panel`** — the panel polls `kitty @ ls` on a timer instead.
  A watcher→file-touch→faster-poll chain is possible but adds a cross-process edge for marginal latency; the
  documented callback is noted here in case panel latency ever matters.
- **`join_shell_words` bash `%q` output** — works through kitty's own `Shlex` (verified against installed source:
  `\ ` and `'…'` parse correctly). Only the `$'…'` ANSI-quote form (paths with control chars) would mangle — a
  path with a newline already breaks far earlier. Note only.
- **Stale-key flap if `ident` is intermittent** — covered by plan 007's design note (close on the verdict's
  agent signal, not on a single `ident` miss).
- **jj/gitless-VCS support in `kittymux_changes`** — T3 Code abstracts VCS drivers; kittymux assumes git. jj's
  colocated `.git` means it mostly works today; a real driver seam is worth it only if a jj-only repo user shows
  up.
- **T3 Code patterns explicitly rejected**: hidden git refs inside the user's repo (violates kittymux's
  never-write-into-repo rule), Effect-style service layers/daemon (kittymux is a config pack by design),
  process-resource telemetry (no long-lived process to monitor).
