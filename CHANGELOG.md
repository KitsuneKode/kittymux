# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/). Versions follow [SemVer](https://semver.org/) once tagged; until then everything below is *Unreleased*.

## [Unreleased]

### Added
- **Brand tiles in the pixel tab bar are lit:** each agent's tile is a gradient between two of its own colours (Gemini's blue into purple, Claude's clay, Codex's green…), with a faint light on its top edge; the split badge too.
- **T3 Code** (`t3`) is a known program: its tab shows T3 Code's own mark (traced from the app's icon by `tools/trace-t3code.py`) on its night-sky gradient.

### Fixed
- **Cursor Agent and Antigravity's trust prompt reads as "needs you".** Their first run in a folder stops at "Do you trust the contents of this directory?" until you answer; kittymux saw nothing there, so the bar, popups and the notch stayed quiet while the agent was blocked. Captured from both agents live.

### Added
- **The pixel tab bar (`kittymux settings on pxbar`, opt-in).** The vertical tab bar drawn as a picture inside the kitty window, as Rex's sidebar looks: tabs grouped under their project (in kitty's order, so nothing moves under the pointer), one row per tab with the agent's or program's real mark on a tile, the title, and one end mark (a working loader, a done dot, a failure cross, the needs-you chip); a second line only when it has something to say (the question, what failed, "Working · 3m"). Under the pointer a row lifts and its end turns into a close cross; clicking it closes the tab, and a working or waiting agent asks on its row first (a second click closes). Large groups of settled tabs fold to their label; clicking the label opens them. The header has search and a fold-to-rail button (the rail's top tile opens it again); the footer has a Filter field that opens the command palette and shows its chord, then the needs-you inbox, usage and the keys sheet, each running the action its key maps. The working loader is a wave that moves (kittymux-pxwave.slang, run by kitty only while a row it shows is working, at 15 fps, about 2% of a core; still with `motion` off), a finished agent's second line shows its diff in colour, and a settled agent shows its age. More tabs than fit: the bar scrolls so the tab you are in stays on screen with a little room around it, and "↑ N above" / "↓ N below" page when clicked. Progress (OSC 9;4) is a track with its fill and the percent. With `background_opacity` below 1 the bar is glass, a little denser than the terminal, and the terminal rests on it as a card with rounded corners (Rex's look); the hover is half a step under the active card and lifts a settled title. Needs cairo, pango and rsvg; the hover, the cross and the card need kitty's custom shaders (kitty 0.49 or newer with `slangc`), and without them no click closes a tab. A muted agent shows as muted (no needs-you chip, not counted); waiting and finished rows keep their age beside the mark, and unread output gets its dot. kitty's own red overflow `…` is not drawn over the picture. When kitty hides the bar (one tab under `tab_bar_min_tabs 2`) the picture goes with it, so no sidebar is left behind the terminal's text. Your own `background_image` is replaced while it is on and comes back when it is off; the picture also goes when the bar moves to the right edge or the kittymux client attaches, and a picture that fails to draw falls back to the cell bar. Off, the cell bar is exactly as before.
- **`tests/shot_states.sh`**: every agent state and edge case on one screen, dark and light, at three widths, plus 40 tabs.

### Fixed
- **A usage limit's countdown agrees with the agent.** `↻1h` sat beside "resets in 2h": the countdown floored like an age. It rounds to the nearest unit now (`↻2h`), never under `↻1m`.
- **A kitty that has run since before an upgrade keeps kittymux's bar.** After `kittymux upgrade`, a kitty started on an older release could show kitty's own plain tab bar (bare titles, no marks, no header): the new bar asked the reload helper the kitty already had in memory for something only the new helper has, and failed before it could refresh it. The bar now refreshes the helper first, so the same reload that brought the problem fixes it; no restart needed.

### Changed
- **The working mark is a quarter-turning circle (`◐◓◑◒`), not braille dots.** At the end of a row the dots sat tiny and grey and read as a `⋮` menu button that does nothing; the circle reads as work turning over. It still steps once every 3 s and never spins.
- **Tab progress is a hairline, not a tinted block.** An OSC 9;4 report filled the card from the left with a tint that, in a light theme especially, read as a second selection. It is now a coloured underline under the tab's last line (kitty's own underline colour, so it stays crisp in cells), the percent beside it, in the accent while it runs, yellow when paused and the alert colour across the whole tab on an error. The selection is the only filled card again.
- **Bar cards (`kittymux cards`):** the hover highlight now spans the whole row like the active card (it stopped about five cells short of the tab number), and the soft shadow no longer flecks the space under letters in a light theme (a glyph's anti-aliased edge can match a card colour; a card pixel now has to be part of a flat run).

### Added (the kittymux client)

- **`kittymux client`**: a sidebar beside kitty, drawn by Quickshell (Qt's software renderer by default, OpenGL with `KITTYMUX_CLIENT_GPU=1`) instead of in terminal cells. It shows every tab of every running kitty with a two-line header (where you are, then what needs you), the tabs grouped by space or by state (`g`, shared with the panel), a state ring around each agent's mark (a calm turning arc while working, the percent when the program reports one, orange when it needs you, green when finished, red on error), one hover highlight that glides between rows, rolling tabular numbers, and an inline right-click menu (Jump, Mute). Colours come from the live kitty theme. It uses no CPU at rest and about 1% while an agent works (measured under Xvfb). See the client page in the user guides.
- **The client can sit in kitty's own bar (Hyprland, experimental).** In attach mode (`KITTYMUX_CLIENT_MODE=attach`; the client docks by default), the client is laid exactly over each kitty window's vertical bar: kitty keeps the bar's place, background, blur and divider and draws no tabs there, and the client draws the content on top, so the sidebar is part of the window. It follows the window through Hyprland's events (fading out while windows move, back where they land), hides on other workspaces and under fullscreen or floating windows, and kitty draws its own tabs again when the client stops. One accent mark says where you are and glides to the tab you switch to.
- **`tabs.json`**: every tab of every running kitty, with the pane that speaks for it, its project, branch and hue, and the kitty theme's palette, published by the scanner only when something changed (docs/inbox.md). kuwai's Agents tab already reads it.
- **`kittymux mute --pid P --window W`** (and `unmute`): mute one pane of a named kitty without a socket, for a client that runs outside kitty.

### Added
- **Group by priority.** `g` in the panel lists every tab, across sessions, under Needs you, Working, Finished and Idle; `g` again goes back to spaces, and the panel remembers which. `Home` (and `G`/`End`) still go to the ends.
- **Mute an agent.** `kittymux mute [TAB]` (`unmute`, `mute --list`), `m` on a tab in the panel, or a right-click. A muted agent keeps running and stays listed with a bell-slash, but sends no popup or bell and never counts as "needs you" (not in the panel's chip, not in a space's ring). Its events still reach the inbox. `agents.json` rows gain `muted` and the document gains `needs_you` (additive, version 1), so a desktop shell can honour it.
- **Confirm closing a busy agent.** Closing a pane or a tab whose agent is working or needs you (`ctrl+shift+w`, `ctrl+shift+q`, `ctrl+alt+q`, `ctrl+alt+shift+w`, the leader's `x`/`X`) asks first on one line: the tab's row in the bar says "Close? Press again" (a pane title bar, when kitty draws one, says "Close Claude Code? It is working · ctrl+shift+w again"), and the same key within 4 s closes. No dialog and no focus change; the question lapses on its own. Anything else closes exactly as before. `kittymux settings off closeguard` stops asking.

### Added
- **The pane that needs you is marked where it is.** In a split, the divider beside a pane whose agent is waiting (or hit its limit) takes kitty's bell colour (`bell_border_color`) until you go there. kitty draws it: kittymux sets the window's own `needs_attention` flag without a bell, so nothing rings and focus never moves; a muted agent is never marked, and a real bell's mark is never taken away. `kittymux features off ring` turns it off.

### Changed
- **kitty's own bar speaks like Rex.** An agent tab's second line now starts with its state in words, in the state's colour (Working, Needs you, Finished, Limited, Error), before the folder line; the glyph at the right stays. The header's second line says its counts in words when they fit (`10 tabs · 1 needs you`) and keeps the `! 2  ✓ 1` badges when they do not.
- **The pixel panel, tidied after review (wave 3.1).** While a docked panel runs with its Agents list in pixels, the tab bar of the kitty it watches is hidden: both used to list the same tabs. It stays hidden while you look at Usage, Inbox or Settings (so your panes never resize when you change views), and comes back when the panel closes, when you turn `deckpx` off, or when the panel is too small for pixels, even if the panel was killed (the scanner sweeps a dead panel's cover); `kittymux settings off pxcover` keeps the bar. A split's pane rows say what runs in each pane (Codex, `pnpm dev`, zsh) instead of the repo twice. The key hints are drawn in the panel's own type, and the prompt preview under the list is gone (the pane shows it). The accent hairline around the current tab is dimmed to about 45 % so the state colours lead. The cell bar no longer fills a tab's card for OSC 9;4 progress (it read as a glitch); the percentage stays where the tab number was.
- **The pixel Agents panel, redesigned (wave 3).** A two-line header (the session, then the machine and tab count) with an orange "N need you" chip that jumps to the first question. One list, Machine → Space → Agents: each space heads its own tabs with its loudest state as a count in a ring; with no named session, the repo and branch a run of tabs sits in is the space. Each tab is a vertical pill: the agent's mark (monochrome) inside a state ring, the title, then a state word (Working, Needs you, Finished, Error, Limited) with its age, progress, pull request and ports. Colour is only for state; the accent is only the hairline around the tab you are in, and selection and hover are lighter surfaces. No gradients and no shadows.
- **Calm motion: the working mark steps, it never spins.** The bar's working glyph steps once every 3 s instead of spinning at 10 fps, and the panel's working ring steps a quarter turn every 3 s instead of looping at 80 ms. A state change in the panel cross-fades in about 150 ms. Under a software-rendered kitty with one working agent, `tests/shot_premium.sh` measured the main kitty at about 72% CPU before and a few percent after. Switching `motion` off now puts the still frame up at once.
- **Pane title bars show the state as a pill.** The state's word in a rounded pill of its colour (kitty's title bar honours background colours), shrinking to the mark when the pane is narrow. The pane header no longer animates.

### Added
- **`tabs.json`: the bar's tabs for a desktop shell.** `$KITTYMUX_STATE/tabs.json` lists every tab in every running kitty — the title, place line, state, age and progress the vertical bar already draws — so a shell can paint them in real pixels without deriving them again. Mode `0600`, schema version 1. Each kitty replaces only its own windows. The file is rewritten at most once every 250 ms, and only when something other than the timestamp changed.
- **`kittymux cards`: the bar's cards in pixels.** kitty 0.49's custom shaders post-process the rendered frame, and kittymux now ships one (`assets/shaders/kittymux-cards`) that touches only the tab bar: the active card's square cell corners become anti-aliased rounded ones, its top edge catches a faint sheen, a soft shadow falls under it, and on a tab change it glows and settles (kitty's `tab-change` animation, 420 ms ease-out). The shader derives the bar and card colours from kitty's own background and foreground exactly as `kittymux_theme` does (sRGB blend, rounded per channel), so every theme works without a generated file. Opt-in, gated on kitty ≥ 0.49.0 and `slangc`, and shares the one `custom_shaders` line with `kittymux dim`.
- **The bar cards follow the pointer, and the other fills round too.** The row under the pointer lifts by a quieter step of the card's own mix (kitty sends the bar no hover, so the shader reads the pointer). It redraws when the pointer moves and does not keep drawing once the pointer is still. A progress fill, the paused (waiting) tint and an error fill round at the card's outer corners; the end of a partial fill stays square. `kittymux cards glass` lets the bar's own pixels go translucent for a compositor blur behind the window. Text and the cards stay opaque. Glass needs kitty's `background_opacity` below 1.

### Fixed
- **A kitty whose config dir links only some kittymux modules loads the bar again.** The bar, the bar-size hook and the watcher imported `kittymux_reload` before they had put their own folder on Python's path, so a partial install (and CI's smoke rigs) failed to load the bar and never started the scanner.
- **The pixel Agents list keeps the accent for one thing.** A keyboard selection was a pink ring on top of the current tab's pink bar and a pink mascot tile; it is now the same raised neutral card as the active row, the chevron and the mascot tile are neutral, and the accent marks only the tab you are in.
- **The bar says something on a plain shell.** A shell in your home folder titles its tab `~`, the folder line then repeats the title and hides, and the row was a bare tilde with a lone number under it. Now the tab is called **Home** and its second line names the program it runs (`zsh`, or the app in front). With no session name the header names the machine (`archlinux` over `2 tabs`) instead of a generic `Tabs` over the host, and the mascot is drawn in the text colour — the accent stays for selection and focus.
- **`kittymux workflow find-session` no longer logs a burst when kitty cannot take a snapshot.** The session picker asks once per session, and each call used to fail immediately and write `cli-errors.log`. It now waits 0.5 s, then 1 s, then 2 s, logs that one line, and gives up. A later call in the same few seconds returns at once and does not log again. Any other failure is unchanged.
- **An agent error keeps its own words, and a new one is said again.** The bar and the panel showed the hook's message over the OSC 7501 reason. They now show the reason. A later, different error report notifies again; the same report does not, including after a prompt or a limit. A failure only mentioned in other text no longer swallows the OSC popup. A usage limit on screen still outranks a "blocked" report.
- **The status relay clears a stale report and does not wait forever.** Starting `mux-pty` clears a previous `kittymux_psp` on the window, and a command that ignores the hangup is killed after a short wait instead of leaving the relay blocked. An agent started as `mux-pty -- <agent>` is recognised, including the names that only match their own argv.
- **A jump is not marked read when the OS window could not be raised.** With Hyprland running, `inbox jump` acks the event only after the compositor focus succeeds. A kitty that is not a client of this Hyprland (an X11 window) is still focused. The focus tag is put back to a title you set yourself, and a slow compositor query no longer stretches that wait. The agent picker's Hyprland match is this kitty's process, not the first window that shares the title.
- **The bar keeps the marks at the right edge.** On a 28-column bar the last attention badge stays on the header line. A progress percent on a tab with no folder line no longer covers the state mark. The first tab is labelled when its session is not the one the header names. A peek card that cuts a long title shows the cut-off tail under the header.
- **Zoom from a half-maximized pane fills the tab.** An axis that was already maximized is left as it is (kitty's maximize toggles, so asking for it again would undo it). The action names the window the layout was read from, and a failure is a notification: the key runs in the background.
- **Hyprland 0.57 can focus the window a jump, the agent picker or a moved tab asks for.** `hyprctl dispatch focuswindow` is no longer a dispatcher there: the compositor runs Lua (`hl.dsp.focus({window = 'address:…'})`) and rejects the old line. Jumps from a notification already used the new form; the agent picker, a focus of an OS window and a moved tab still sent the old one, so they stayed on the source workspace. One helper (`kittymux_wmfocus.focus_address`) probes with a fake address — the reply has to be that the window was not found, and the probe never names a real window — and uses the Lua form when that answers, the classic dispatcher when only that one does. Shell and Python both call it.
- **Zoom fills the tab, and it is quiet on the stack layout.** `ctrl+alt+z` and leader `z` maximize both axes (plain `layout_action maximize` is horizontal only) and pressing either again restores the splits. On the stack layout the focused pane already fills the tab, and `layout_action` there does nothing and rings the bell, so zoom leaves the stack alone. `ctrl+alt+space` (and leader `space`) cycles splits and stack.
- **An agent-reported error is no longer shown as done.** OSC 7501 `error` was stored like a completion and its message was dropped, so a quiet screen grew the unseen checkmark and a "done" notification, and a screen that still looked busy stayed "working" and never showed the failure. `error` is now its own state (`✕`, the alert colour) in the scanner, the inbox, the notification, the bar and the panel. The message is kept. A permission prompt or a usage limit still comes first. A mute holds the popup; the event still reaches the inbox.
- **Fan-out starts the status relay.** With the Agent status relay switch on, `kittymux spawn` ran agents behind `mux-pty` and `kittymux fanout` did not, so fanned-out agents never reported OSC 7501. Fan-out now passes the relay the same way spawn does.
- **The peek card uses the same title as the bar.** It showed the raw window title, and drew that title twice (once in the header, and again underneath even when it already fitted). It now uses the shared title cleaner and draws the title once.
- **A notification's jump no longer moves your other monitor.** One kitty is usually several OS windows, often on different workspaces; the jump (a notification's action, `inbox jump`, the picker, reopen) asked Hyprland to `focuswindow pid:<kitty>`, which focuses whichever of that kitty's windows it lists first. Jumping to an agent on workspace 3 could switch the laptop screen to workspace 1. kitty now focuses the window and its tab first, and the compositor is asked for exactly the OS window holding it (its address, found by title; two look-alike windows are told apart by a unique title for a moment, then the title is handed back). New `kittymux_wmfocus`. Notifications also carry `x-kittymux-pid` and `x-kittymux-window` hints, so a notification center can jump later through `kittymux act` after the notification's own helper has gone.
- **Vertical bar: error progress, header session, host line.** An OSC 9;4 error at 0 % no longer drew an empty card or hid `failed` on a tab with no folder line; the card fills in the alert colour and `failed` shows on the title row. The header names and counts the **focused** session (not tab 1's), and a long `host · N tabs` line is clipped so the `!` and `✓` badges stay on a 28-column bar. Kitty counts only running and paused windows in a tab's progress total, so an error or an unknown-amount report was never drawn at all before; the bar now follows the window kitty marks as the tab's progress window.
- **A tab that disappears leaves evidence.** kitty keeps no record of who closed a tab, so the scanner now writes a `closed` decision for every agent window that vanishes: what the agent was doing when last seen, how many agent windows went in the same seconds and how many shared its tab. `kittymux explain` says it in words ("with 1 other agent window (1 in the same tab): a tab or window was closed, the agent did not quit"). Two or more at once means a close action, not an agent exiting.
- **A key that could not reach kitty leaves a trace.** Commands bound to a key print their errors nowhere, so "the key does nothing" had no explanation. The "no kitty socket" message is now one wording everywhere (it names the directories it looked in and the fix), and a command without a terminal also writes one line to `cli-errors.log` in the state directory, which `kittymux doctor` shows. Nothing from a screen, title or agent is stored there.
- **One place for every switch: `kittymux settings` and the panel's Settings view.** About twenty on/off settings (the bar's pieces, notifications, bells, autosave, the journal, change tracking, focus on a bell, resume without asking, live usage) each had their own variable and flag file, read in its own place; there was no list. They now live in one catalog. `kittymux settings` shows each one, what it does and why it is on or off; the panel has a fourth view (the gear pill, key `s`) with the same list: `space` toggles, `p` presets, `r` resets, a click on the state toggles. A setting held by your environment shows `env` and is locked; one that is risky to turn on (live usage, focus on a bell, resume without asking) asks first and says what changes; ten quick toggles are one reload. Existing variables and flag files keep working exactly as before. One tightening: `KITTYMUX_USAGE_LIVE=off` (or any word that is not an explicit yes) no longer turns live usage ON, as it used to.
- **Eleven overlays no longer stack.** Pressing the chord of the sessionizer, layout picker, project picker, agent picker, cwd HUD and the rest a second time opened a second overlay on top of the first; each now closes its own (the deck, `ctrl+alt+b`, is the exception: the docked panel is the same program, and closing it by chord is not wanted). A test lists every overlay bind that lacks its twin.
- **A command with a missing option value stops instead of guessing.** `kittymux spawn claude --cwd`, `sessions new x --cwd`, `fanout "…" claude --name`, `explain --window` and `hooks --settings` read the missing value as an empty string (a spawn in the wrong directory, or a traceback). They now say `--cwd needs a value` and exit 2. `sessions restore` no longer claims "opening in a new kitty" when `kitty` cannot be started.
- **Commands started from a window-manager bind act on the kitty you are in.** `layout`, `sessions`, `changes`, `snooze`, `explain`, `screenshot` and `dim` took "the newest kitty"; they now take the one with the keyboard focus (a command started inside a kitty still acts on that kitty). When a command has to guess, it says which kitty it picked, to a terminal.
- **The shell and Python agree on which kitty a command belongs to.** `lib/socket.sh` had no `KITTY_LISTEN_ON` step and ignored `KITTYMUX_SOCKET_DIRS`; a table test now runs both resolvers over the same sockets and environment.
- **The docked panel watches the kitty you pressed the key in.** `mux-panel` looked for the active kitty at `/tmp/mykitty-<pid>` (your sockets live in `$XDG_RUNTIME_DIR`), found nothing and fell back to the newest socket. With a second kitty open (a scratch terminal, a new window) the panel then listed and acted on that kitty: clicks and keys did nothing useful until you opened yet another one. It now uses the kitty that started it, then the focused one, and only then the newest. `lib/socket.sh` gains `mux_socket_for_pid` and `mux_own_socket`; `mux-panel target` prints the kitty a start would watch.
- **A kitty left open for weeks no longer collects state.** The unread-window set, the session journal's in-memory copy, the tab bar's error map and the scanner's debug logs are capped, and the decisions and change files of kitties that exited are removed with the rest of their state. A weekly soak in CI measures memory, descriptors, threads, zombies and the state directory's size.
- **`kittymux panel summon` and `dock` work.** The CLI rejected both with a usage error although its usage line, `mux-panel` and these notes list them.
- **Pulling a pane out (or in) from the deck no longer freezes the panel or keeps your keyboard.** `t` (pane → its own tab) and `a` (absorb a tab) ran their remote-control calls on the panel's UI thread, up to 4 s each, so clicks and keys did nothing meanwhile, and they never gave back an exclusive keyboard grab, so the next keys went to the panel instead of the window you had just been put in. The calls now run on a worker and the grab is released afterwards, as a jump already did. Not verified on a compositor: the layer-shell grab cannot run under a virtual display.
- **Panel clicks on Inbox, Settings and Usage stay in the scrolled body.** Hit regions used `2 − scroll`, so after you scrolled down, a click on the summary header (rows 0–1) could still hit a filter chip, preset or tile that had moved off-screen. Clicks now map through body line coordinates and ignore screen rows above the body; a click on an Agents row selects and jumps even when you had not hovered that row first.
- **The panel takes keys the moment you open it.** The docked panel only accepted the keyboard after a click, so Super+N and then `j` did nothing. Opening it now *summons* it (an exclusive keyboard grab); `esc`, `q`, a jump, `kittymux panel dock` or 12 s without a key give the keyboard back, so a forgotten summon cannot trap your typing. New `kittymux panel summon|dock`; pure rules in `kittymux_panelfocus`.

### Added
- **A shell can watch who is working without parsing a menu.** `$KITTYMUX_STATE/agents.json` (schema version 1, mode 0600) lists every agent in every running kitty: the status-contract state (`limited`, not `limit`), the icon basename, the directory, and the same `jump` object `kittymux act` accepts. It is rewritten only when something visible changed. Inbox events gain `source` (`agent` or `tool`) so a sudo prompt is not an agent; `sources` is unchanged. Notifications add `x-kittymux-event`, `x-kittymux-agent`, `x-kittymux-brand`, `x-kittymux-state` and `x-kittymux-source`. Jump focuses that window and acknowledges it, the same end state as `kittymux inbox jump`.
- **The panel's Agents list can be drawn in pixels.** Opt-in switch `deckpx`, off by default (`kittymux settings on deckpx`). The same snapshot as the cell list: sessions, split panes only when you open them, the same states, and an OSC 9;4 hairline from the progress the bar already reads. Keys, the footer and the other views stay as they are. If the terminal cannot draw images, or you turn the switch off, the cell list is what you get. The spinner is kitty's own animation, so an idle panel does not redraw to spin it.
- **Agents can tell kittymux their status themselves (OSC 7501).** Claude Code, Pi and Crush report working, blocked (with the question or permission), done and error through the Program Status Protocol, which kitty 0.49 drops. With the new opt-in **Agent status relay** switch, `kittymux spawn` runs agents behind `bin/mux-pty`: a byte-transparent PTY relay that answers the protocol's probe, keeps the reports and hands their summary to kitty as the window's `kittymux_psp` user variable. The scanner treats it as the strongest evidence (blocked → waiting with the agent's own words, done → the agent's word, error → its own state with the message kept), with the screen markers as the fallback. It only inserts its own sequence at a clean point of the stream (never inside an escape sequence, an image chunk or a UTF-8 character), follows the window size and exits with the agent's status. Works by hand too: `mux-pty -- claude`. New `kittymux_psp` (parser, records, mapping; tested), `tests/test_mux_pty.py` (end to end in a private pty) and `tests/smoke_psp.sh` (a real kitty, with a control window that must show nothing).

### Changed
- **Pane title bars keep the tab's place.** Each bar leads with the agent or program icon and a bold name (`Claude Code`, `nvim src/main.rs`, or the project name for a plain shell), then the same folder line as the vertical bar: project-relative path, the project's own colour, and the branch. A name that already is the project is not written twice (`alpha  ⑂ main`, not `alpha alpha`, and `src/ui` rather than `/alpha/src/ui`). The state mark and the OSC 9;4 percent sit on the right. A focused pane is bright; the others recede. A narrow bar gives up the path (cut in the middle), then the branch, then the name; the state mark stays. `kittymux features off panetitle` still hands the bar back to kitty's own title.
- **A tab shows the progress its program reports.** Programs that send OSC 9;4 (kitty keeps it per window since 0.42: package managers, `curl`-style downloads, build tools, agents) now fill their tab's card from the left like a progress bar, in a soft tint of the accent; the percent takes the tab number's place. Paused fills in the waiting colour, an error in the alert colour and says `failed`, an unknown amount tints the whole card. With several windows reporting, the tab shows their mean, as kitty does. Try it: `printf '\e]9;4;1;42\e\\'` (and `printf '\e]9;4;0\e\\'` to clear). New `kittymux_progress`; the slim rail is unchanged.
- **Tabs are grouped by session in the vertical bar.** Where a tab belongs to a different kitty session from the one above it, a heading with that session's name (`Other tabs` for tabs in none) comes first, like folders in Rex's sidebar. Not yet looked at with two sessions open: the screenshot rig starts a single session.
- **The bar's header names the focused session and the machine.** It said `TABS` over `N tabs`; it now shows that session's name in full weight over `host · N tabs` (and the attention badges), as Rex's sidebar does. The name and tab count follow whichever session your active tab belongs to, not tab 1's.
- **The vertical bar reads like a sidebar, not a list.** The active tab is an inset card (a column of the bar's colour on each side) instead of a full-width fill with an accent stripe, and tabs are separated by their blank row instead of a hairline rule. The coloured stripe now means one thing only: a tab that needs you. The slim rail is unchanged.
- **Tabs are called by what they are about.** An agent's product name ("Claude Code") or a sentence of its own reply ("I can't do that…") used as the window title no longer becomes the tab's name: the tab is called by its project. Titles are cleaned (markdown, quotes, trailing punctuation, and a `| folder` suffix some agents append when it is exactly the tab's project) and cut at a word. The text of a tab you named yourself is never touched. Bar and panel share one pure module (`kittymux_titles`); `kittymux features off titles` restores the raw title.
- **The panel's Agents list is calmer.** A split tab starts closed (`▸ 3 panes`; click it, or `→` / `o`, to list its panes; hovering and refreshes never open one). The session header hides when there is only one unnamed group, says `other tabs` otherwise, and shows how many of its tabs ask for you. Rows say how long they have waited (`needs you 4m`, `limit hit 1h`, `done 3m`); the words shorten before they take room from the branch. PR numbers and ports no longer wear the "working" blue.
- **`?` in the panel** shows the keys of the current view (a keycap at the right of every footer does the same). Empty lists and empty searches say why. The preview drawer drops blank lines, box rules and TUI hint footers.
- **Number keys: panes on `ctrl+alt`, tabs on `alt`.** `ctrl+alt+1..9` focuses pane N of the tab (the digit `ctrl+alt+e` draws on each pane) and `ctrl+alt+0` the last pane; `alt+1..9` jumps to tab N and `alt+0` to the last tab (the `!scratch` tab is passed over). The `ctrl+alt+shift+1..9` aliases are gone: one chord per job. New workflow ops `kittymux workflow nav last` and `workflow pane last`.
- **Equalize moved to `alt+shift+=`** (it was `ctrl+alt+0`), next to the resize keys `alt+shift+h/j/k/l`, which now move the edge about 3 columns a press (they moved about 1). `ctrl+alt+=` stays Hyprland's.
- **Every rig that starts a private kitty now clears the identity of the kitty you run it from** (`KITTY_WINDOW_ID`, `KITTY_LISTEN_ON`, `KITTY_PID`, `KITTYMUX_TARGET*`), and `smoke_panes.sh` ends with a focus tripwire on every other kitty. A key-bound background process inherits kitty's own environment, so a rig started from a terminal inside a live kitty used to drive that live kitty with the CLI-backed keys.

### Changed
- `ctrl+alt+enter` splits below and `ctrl+shift+enter` to the right; the README says so (it used to say "+shift").
- Recommended kitty setup is now `allow_remote_control socket-only` + `listen_on unix:${XDG_RUNTIME_DIR}/mykitty`; `kittymux doctor` warns about `yes` and a `/tmp` socket. Every smoke test runs under `socket-only`.
- A completion notifies only with a known duration ≥ 15 s after a 5 s settle; a hook-announced turn ends only with the agent's own `Stop`. Screen-only completions need ≥ 60 s of work to pop up.
- Bar redraw 6.0 → 2.1 ms with 23 tabs; the spinner ticks unfocused windows at half rate; resize touches only the visible tab per event.

### Fixed
- **kitty crashed (SIGSEGV in libpython) because of how kittymux replaced its timers.** kitty runs every due timer from a snapshot; a callback that removes another due timer (a config reload replacing the scanner's timers) left kitty calling a Python function it had already released. Every kittymux timer now gets a callable that cannot be freed (`kittymux_timers`), and a tick of a removed timer is ignored. `tests/smoke_timers.sh` reproduces the crash with a raw timer pair and shows the fix survives it.
- **Your own scripts and their keys stopped working after the control socket moved** to `$XDG_RUNTIME_DIR` (the scratch-tab chords for nvim/hypr/zsh/kitty config, font toggle, snapshot, session cycling…): they look only at `/tmp/mykitty-<pid>`. See `socketlink` above.
- **The keymap overlay listed 14 junk rows** (`--mode spawn`…), raw action names (`goto_tab`, `scroll_page_up`), resize keys without a direction, and `ctrl+alt+[`/`]` as "last pane". Fixed at the source in `bin/mux-keys.py`; the spawn-mode chord is listed.
- **A busy line above Devin's idle prompt made a tab read as working** (a pasted Codex log line "Working (1s • esc to interrupt)"); Devin's composer says "Ask Devin to build features" only when idle.
- The pace mark on a usage gauge was a hole that looked like a broken bar; it is a notch now. A selected Usage or Inbox card is marked by a stripe, not a band floating above it.
- The mascot glyph vanished from every running kitty after `kittymux upgrade`: the installer re-copied the (identical) icon font, and the bar hides the glyph when the font file is "newer than the kitty". The installer now copies
  only a changed font and the bar judges the font by content fingerprint, not timestamp.
- Tab clicks that silently did nothing (the 5–14 px gap between kitty's click rule and `drag_threshold`); a stray middle-click no longer closes an agent tab.
- Notifications that forced focus to the agent's window (compositor `focus_on_activate` + a bell): no bell is sent where it would steal focus.
- `packaging/PKGBUILD` now ships `open-actions.conf.tpl`.

### Security
- `kittymux pick` rendered raw window titles: a title with a newline/NUL/ESC/bidi override (any program can set one) could forge rows or shift the indexes a menu answers with. All shown text is sanitised and a row with a control
  character is refused at the menu boundary; `mux-agents.sh` scrubs the same characters. Snooze moved from a window variable (settable by any program in the window) to a private file. `uninstall --purge` refuses to delete
  a `KITTYMUX_STATE` that is `/`, your home or above it, a symlink, or not recognisably ours. A command started inside a kitty acts on that kitty, never on "the focused one". See [docs/audit-2026-10-02.md](docs/audit-2026-10-02.md).
- Secret-looking flag values are redacted from printed `sessions list` / `sessions history --json`; see [SECURITY.md](SECURITY.md) for the threat model.
