# Audit — performance, memory, security, correctness

Scope: the whole repo as of 2026-10-01. Method: profiling a 20-tab bar with a running spinner, a 2-minute
RSS soak, reading every place untrusted text or shared paths are touched, and end-to-end runs in a private
Xvfb + kitty (`tests/smoke_*.sh`). Numbers are from the author's machine, not a benchmark suite.

## Performance

| Change | Before → after |
|---|---|
| Tab bar reads only the foreground *leader* (`tcgetpgrp` + one `/proc` read) instead of kitty's `foreground_processes` (walks all of `/proc`) | `draw_tab` 1.5 ms → 0.09 ms (≈17×) |
| 20 tabs + 6 working agents, spinner running | ≈62 % → ≈10 % of a core |
| Branch/worktree label read from `.git/HEAD` (mtime-cached, bounded) instead of a `git` subprocess per tab per redraw | one process per tab per second → zero |
| Scanner: agent windows only, 0.5 s tick (2 s with no agent), verdict file rewritten only on change (+3 s heartbeat) | no steady-state disk churn |
| Spinner repaint fixed (see Correctness) | 1 → 10 distinct frames/s on an idle window |

## Memory & resource leaks

- 120 s soak, 20 tabs, 6 agents, spinner running: RSS flat (139 MB → 139 MB after start-up settle).
- Timers: scanner and spinner timer ids live in `sys.modules["_kittymux_scan_rt"]`, so a reload cannot forget
  a live timer; `ensure_started()`/`restart()` never stack (unit-tested, including `importlib.reload`).
  The spinner timer removes itself when nothing is working.
- Per-window bookkeeping, verdicts, notification timestamps are dropped when the window closes; caches are
  bounded (git: 256 entries; logs: 64 KB cap).
- Stale `panes-<pid>.json`, `scan-<pid>.json`, `layout-<pid>.json` of dead kitties are removed.

## Security

- State dir `0700`, every file `0600` from the first byte (they contain tab titles, agent messages, screen lines).
- Text from terminals (user vars, screen lines) is stripped of control characters, bounded, and markup-escaped
  before it reaches the bar or a notification; `notify-send` is called with `--`.
- Remote control: only sockets *owned by the current user* are used (a planted socket in `/tmp` is ignored);
  the docked panel's socket lives in `$XDG_RUNTIME_DIR`; `doctor` warns about `listen_on` in `/tmp`.
- `hooks --install` backs up first, never widens file permissions, never overwrites an existing backup;
  `hooks --remove` removes exactly the `mux-status` entries and nothing else.
- The geninclude script never raises `SystemExit` (it runs inside kitty's interpreter and would quit kitty).
- The scanner reads pane text **locally** and never transmits it. Only a matched marker + one ≤100-char line is kept.

## Correctness bugs found and fixed

1. **Spinner stutter.** `mark_tab_bar_dirty()` updates the bar's cells but does not make kitty *render*; frames
   appeared only when something else (cursor blink, output) repainted — ≈1 fps on an idle window. Fix: also
   `mark_os_window_dirty` + `wakeup_main_loop`. Regression test counts distinct frames in 3 s.
2. **False "waiting".** Agents without hooks were "waiting" whenever their title was quiet for 15 s, so a Devin
   *thinking* for 37 minutes showed `!`. Silence is no longer evidence; states come from what is on screen.
3. **Stuck "!" after finishing (Claude).** The idle Notification ~60 s after `Stop` flipped `done` to `waiting`
   forever. A hook "waiting" now only counts when its message reads like a request; otherwise it is an unseen completion.
4. **Spinner only for hook-reported work.** Screen-detected work never started the spinner timer. One resolver now
   drives bar, deck, panel and jump queue.
5. **Vertical tab drag-sorting.** Kitty's tab extents skip the blank spacer line between tabs; a pointer over it made
   the drop logic swap the dragged tab with the *last* tab (a third of all positions). Hit testing now snaps to the
   nearer tab (`snap_tab_id`), covered by unit tests and a real click test.
6. **Upgrade-under-a-running-kitty.** kitty caches watcher modules and Python caches imports; the tab bar now
   reloads helpers on every load and restarts the scanner. `tests/smoke_reload.sh` reproduces the stale-module
   scenario with the previous release's module (and fails on purpose with `SMOKE_KEEP_STALE=1`).
7. **sys.path priority.** Modules inserted their own directory *before* the config dir, so the config dir won and
   tests could import the installed copy. Own directory now wins.
8. Earlier in this series: stale-module `AttributeError`, geninclude `SystemExit` killing kitty, a CLI that targeted
   the wrong kitty from a stale `KITTY_PID`, unix-socket paths > 107 bytes, `kitten panel` arg handling.

## Not audited / known gaps

- No fuzzing of the agent screen patterns; a hostile program can print "Do you want to proceed?" and make its
  pane look like it is waiting (cosmetic only — nothing acts on it except a desktop notification, rate-limited).
- macOS / X11 panel / non-Hyprland compositors: see `compatibility.md`.
- The usage collectors (`python/collectors/`) talk to vendor endpoints only with `KITTYMUX_USAGE_LIVE=1`; their
  network code was not re-audited here.
